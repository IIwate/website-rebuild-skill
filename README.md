# website-rebuild-skill

给一个网址，让你的 AI agent 把那个网站**逐行复刻**出来，并且能证明复刻得对。

它不是"做一个看起来很像的页面"。它把源站的实现当作规格书：先把整站抓成只读证据，再从压缩过的代码里逐行还原逻辑，最后用一整套自动验收门证明"复刻侧和源站在做同一件事"——包括逐像素比对。

遵循 [Agent Skills 开放规范](https://agentskills.io/)，为**任何支持 skills 的智能体**设计。Claude Code / Claude Desktop 只是其中之一，任何实现该规范的 agent runtime 都能加载（skill 内的提问方式与脚本调用会按运行时能力自适应，不绑定特定产品）。

## 它替你做什么

你给一个网址，agent 会自己走完这条链路：

| 阶段 | 它做什么 | 你会看到 |
|---|---|---|
| **判级** | 先探测这个站属于哪一类，能不能做 | 判级结论与依据；不能做会直接说明原因，**不会硬跑产出垃圾** |
| **镜像取证** | 把整站抓成只读快照，断网也能跑起来 | 一份逐文件带校验和的镜像与账本 |
| **逆向** | 把压缩过的代码展开，让复刻里的每一行都能指回源站的哪一行 | 一份逆向笔记，说明这个站是怎么实现的 |
| **移植** | 逐行还原到你自己的工程里，每处改动都标注源码出处 | 可运行的复刻工程 + 逐条登记的差异表 |
| **验收** | 自动比对两侧：控制台、网络、DOM、几何、像素 | 量化报告；差异要么被修掉，要么被登记，**不许糊过去** |
| **收口** | 逐模块清点有无遗漏，并整理版权事实 | 审计记录 + 一份待你裁定的部署评估 |
| **源码化** | 把逐字移植的产物重写成人能读的工程：拆模块、给变量命名、补注释、复制资产 | 一个**可以复制到任何地方独立运行**的源码工程 |

**大概要多久**：单页创意站约 1–3 天（数十次提交）；多场景、重 WebGL 的站按周计。agent 会在开工前给出难度评级与预估。

**它盯着的是"对不对"，不是"像不像"**。最近一个自研 WebGL 引擎站的复刻，三条路由做到了**跨侧逐像素一致**（`meanAbsDiff 0.00`），最终产出 389 个源码模块、中位数 18 行。

⭐ **最后一步是"源码化"，而它必须排在最后。** 重构最怕改完不知道有没有坏；这里在动手之前已经有了一个逐像素精确的裁判，所以每一次拆分、每一次改名都能被证死。**没有裁判的重构是盲改。**

### 全程遵守的六条纪律

它们不是风格偏好。这六条是从实践里挨个撞出来的，违反任何一条都会在后面的阶段以 bug 的形式偿还：

1. **镜像只读**，永不修改——它是全项目唯一的证据基准
2. **以源码为唯一裁决**，不凭肉眼调效果
3. **源站有的都要有，源站没有的不发明**——宁可先不像，也不自创补丁
4. **bug、死代码、怪写法照抄不修**——压缩代码里的每个怪写法都可能是行为本身
5. **有意的差异必须登记**，写清"源站怎么做 / 我们怎么做 / 为什么"——**没登记的差异一律算 bug**
6. **代码与文档同一次提交**

⚠ 第 3 条在最后的**源码化**阶段有一条明确边界：在人写的那份源码里重命名、拆模块、补注释**不算"发明"**——那一份是显式登记的衍生物，不是对源站的断言。但两条硬线不动：**不许顺手重构**（合并重复、提取公共函数、改算法都会让"等价"变得无法判定），以及**注释里的推测必须标注成推测**。

## 这和"扒站"有什么不一样

用 wget、HTTrack、SingleFile 之类的工具把网站抓到本地，也能双击打开、也能离线跑。**如果你只是想留个存档或本地看看，那些工具就够了，不必用这个。**

区别在于：**扒站回答"它长什么样"，复刻回答"它是怎么做到的"。**

| | 扒站 / 镜像 | 工程化复刻 |
|---|---|---|
| **你拿到的 JS** | 压缩混淆后的产物，一行几十万字符 | **模块树**：389 个文件、中位数 18 行，每个文件头标注它来自源站的哪几行 |
| **变量名** | `e`、`t`、`r`——压缩器抹掉的信息回不来 | 有证据可依的**逐个还原**；⛔ **没有证据的宁可不改**——错的名字比 `e` 更有害 |
| **第三方库** | 和业务代码糅在同一个文件里 | **剥离出来**，按源站声明的版本从 npm 装回（版本号是从代码里取证的，不是猜的） |
| **能不能改** | 能改，但你不知道改了什么、也不知道会坏什么 | 能改，而且**一整套自动检查会告诉你坏没坏** |
| **怎么知道对不对** | 打开看一眼，觉得像 | 控制台 / 网络 / DOM / 几何 / **逐像素**五层自动比对，差异要么修掉要么登记 |
| **学得到东西吗** | 学不到——你没有读懂任何一行 | 产出里包含一份**逆向笔记**：这个站的动画怎么编排、场景怎么组织、数据怎么烘焙 |
| **能不能带走** | 能，但它只是那堆文件 | **复制到任何地方、断网安装、直接跑**——资产、构建配置、开发服务器都在里面 |
| **典型产物** | 一堆文件 | 可运行工程 + 逆向笔记 + 差异登记表 + 验收报告 + 版权评估 |

**镜像是这套流程的起点，不是终点。** 第一步照样把整站抓成只读快照——但那份快照在这里的用途是**当裁判**：后面每一次"复刻侧对不对"的判断，都是拿它当标尺量出来的。扒站到此为止，复刻从这里开始。

**一个具体的对照**——同一个站，两种做法拿到手的东西：

| | |
|---|---|
| 扒下来 | 212 个文件，其中一个 **1.25 MB 的压缩 bundle**：three.js、几个库、站点自研代码全糅在里面，无法阅读，也无法拆开 |
| 复刻出来 | 从中分离出 **14,232 行**站点自研代码，拆成 **389 个模块**（中位数 18 行，最大的一个是源站里本来就有的一个 1,013 行的类）；three.js 按取证到的版本从 npm 装回；464 个顶层声明逐个清点无遗漏；复制到仓库外断网跑起来，对源站仍是 **0.00** |

**什么时候用扒站就够了**：只想离线存档、只想看看长什么样，或者目标站不在下一节说的可做范围内。**什么时候值得用这个**：你想读懂它是怎么实现的、想在它的基础上改、想把它的做法学进自己的项目。

## 它能复刻哪些网站

能不能做，取决于一件事：**这个站的"签名行为"（那些让它值得被复刻的动画与交互）住在哪里，以及有什么挡在前面。** 按这条轴分五类：

| 类 | 名称 | 签名行为住在哪 | 结论 |
|---|---|---|---|
| **A** | **客户端行为站** | 全部在客户端静态资产里，且是**命令式**代码（可逐行转写） | ✅ **主场**，直接开工 |
| **B** | **平台包裹站** | 也在客户端，但外面**裹着一层**要先剥掉或先快照的东西（平台层、序列化数据块、运行时接口、第三方资产桶） | ⚠️ **有条件支持**，先剥层再进主线 |
| **C** | **声明式架构站** | 在**声明式的组件树/时间轴数据**里（React RSC 流、R3F + Theatre） | ❌ 逐行转写对它失效 |
| **D** | **服务端行为站** | 在**服务端**（CMS、购物车/库存、A/B 分桶、个性化） | ❌ 客户端没有可移植的东西 |
| **X** | **已消失的站** | 不存在了（域名易主、平台回收、原地替换） | ❌ 没有可镜像的对象 |

**判级看的是实现方式，不是框架名。** "用了 Vue/Nuxt/React 就是 C 类"是最常见的误判，已被实测证伪——决定成败的是**引擎范式**（命令式还是声明式），不是框架。所以要分开问两件事：① 这个框架**下不下发行为源码**？② 下发的东西**能不能逐行转写**？两者都过关才是 A/B。

判级由 agent 在第 0 步自动完成，判定树见 [scope-and-fingerprint.md](skills/website-rebuild/references/scope-and-fingerprint.md)。

### 已跑通的场景（A / B 类）

| 场景 | 覆盖情况 | 实测规模 |
|---|---|---|
| **命令式 WebGL / Canvas 场景** | three.js、自研引擎、GLSL/TSL 逐字提取 | 1.25 MB 单 bundle + 156 个 shader；另一站 47,224 行 three 引擎 |
| **GSAP 时间轴 / 滚动叙事** | 时间轴、ScrollTrigger、自研输入状态机 | 多个获奖作品集站 |
| **烘焙动画与私有二进制格式** | GLB / `.buf` / `.riv` / KTX2，反解成可校验的数值 | 53 个几何文件、170,289 顶点，格式从代码里逆出 |
| **静态构建器产物** | Astro / Nuxt SSG / Webflow 导出壳 / Vite / webpack | 单页站、SSG 站、导出壳站各若干 |
| **各种代码形态** | 压缩、混淆、未混淆都可以 | 全混淆 47k 行；未混淆 974 行；还有完全没有 bundle、逻辑写在模板内联块里的站 |
| **B 类：平台层剥离** | Shopify（平台 / 应用 / 上游主题 / 站点自研四层分离） | 两个 Shopify 店铺，其一是主题 fork 的定制店 |
| **B 类：序列化数据块展开** | Nuxt 等 SSG 把数据编码进页面的形态 | 一个 63.5 KB 的数据块（占文档 54%），展开为 566 KB 结构化数据并逐项比对 |

### 做不了的场景

| 类 | 类型 | 原因 |
|---|---|---|
| **C** | 声明式架构站 | 签名行为在 React RSC 流 / R3F+Theatre 组件树里，**逐行转写失效**——它需要另一套"重构式逆向"，尚未实现 |
| **D** | 服务端行为站 | 行为主体在服务端（CMS、电商库存、A/B 分桶、个性化），**客户端没有可移植的目标**，也没有确定性的验收基准 |
| **X** | 已消失的站 | 没有可镜像的对象。历年获奖站实测消失率约 **29%**——这也是"第一时间镜像"成为第一条纪律的原因 |

三类各自的实测样本见下文[已验证过的网站](#已验证过的网站)。

## 开始使用

**前提**：Node 22+、本机装有 Chrome/Chromium（无头对比用）、`npx` 可用。

**安装**：把 `skills/website-rebuild/` 整个目录放进你的 agent 的 skills 目录。以 Claude Code 为例：

```bash
# 用户级（或项目级 .claude/skills/）
cp -R skills/website-rebuild ~/.claude/skills/website-rebuild
```

其他支持 Agent Skills 规范的 runtime，按其各自的目录约定放置同一份目录即可。

**使用**：给你的 agent 一个网址，说"复刻这个站"或"1:1 rebuild 这个网站"。

**过程中它会来问你**：复刻范围（整站还是指定页面）、外部依赖怎么处置、以及所有涉及"能不能公开"的判断。这些是**你的决定**，agent 不会替你做。

## 关于版权：能不能做，和该不该公开，是两回事

本 skill 面向**学习与研究**用途。产出**默认私有 + noindex + 不部署**——这是一个**保守的默认动作**，不是 agent 替你下的法律结论。

公开之前必须完成逐资产的版权**取证**，而**决定权始终在你**：skill 只负责收集事实、列出选项与各自的风险边界、给出建议，凡涉及"能不能公开 / 部署 / 再分发"，一律显式交回给你。

⛔ 有一条硬规矩写死在 skill 里：**法务考量永远不能削减镜像的完整性**。曾经有一轮以"反正不公开"为由少抓了约 60% 的资产，而所有验收门全程显示通过——从那以后，"不抓"只允许有技术性理由。

## 仓库结构

```
skills/website-rebuild/    # 技能本体，目录结构遵循 agentskills.io 规范
├── SKILL.md               #   主流程 + 判级 + 纪律（激活时整体加载）
├── references/            #   16 份分场景指南（按需加载）
├── assets/templates/      #   文档模板
├── scripts/               #   34 个零依赖 Node 脚本 + lib/ 6 个共用模块
│                          #     判据与源码化之前的全部工序都住这里
└── tools/                 #   源码化阶段的重构器，允许 devDependencies
README.md                  # 本文件
```

⭐ **两个目录的分界是阶段，不是角色**：源码化之前整条流水线**零依赖**——复刻项目要到最后一步才装东西。前面的工序需要真正的 parser 时，`spawn` 一个钉死版本的 npx（`js-beautify` / `acorn`），脚本自身仍然零依赖、仍然可被独立审查。这条线由 `scripts/verify-zerodep.mjs` 看着，因为它曾经**只写在文档里、被违反了八个版本没人发现**。

## 更新记录

每完成一个复刻项目，就把那一轮踩到的坑变成新的纪律或新的检查工具。所以下面每一条，都是某个真实项目里出过的问题。

### 流程与验收体系成型（v0.1.0 – v0.1.11）

最早六个项目提炼出四阶段流程，随后由后续项目逐条打磨验收：门有哪些失效模式、仪器要怎么校准、期望值从哪来。

- **v0.1.0**：首个版本——四阶段流程、六条纪律、判级门，提炼自六个连续复刻项目，适用边界经 43 站实测校准。
- **v0.1.1**：新增 Shopify 平台层指南与流媒体补录；修爬虫的协议相对 URL 处理与"零外联"检查的覆盖面。
- **v0.1.2**：新增场景数值比对、设备能力探测的冻结协议、镜像闭包校验；判级升级为"框架模式 × 引擎范式"二维。
- **v0.1.3**：发现**冻结的盲区**——被冻结分支上挂着的子系统会以"通过"的形式从验收里消失；配套打包字节切片移植工具。
- **v0.1.4**：发现**快门速度**——截图耗时与被测运动全长之比过大时，仪器本身会造出稳定可复现的假差异。
- **v0.1.5**：三条互相印证的验收失效模式（检查点有位置和状态两个维度 / 清点粒度不够粗就会漏 / 把差异区域扣掉等于掩盖缺陷）；调试端口改为确定性分配。
- **v0.1.6**：新增**镜像自检**——参数化的图片 CDN 会让三份不同的图坍缩成一个文件，而"零 404"检查照样显示通过。
- **v0.1.7**："没有任何改动就报错"这条守卫在高频改动的站上恒为真、等于没有，改为**逐条改动各带命中次数下限**。
- **v0.1.8**：期望值必须让浏览器自己算一遍再取；归因之前先校准仪器；确立一条排查顺序——**镜像那侧报错说明检查写错了，复刻那侧报错才说明代码错了**。
- **v0.1.9**：登记表复核改为固定动作；新增一类失效模式——**把会流动的量（时钟）写进了记录**，症状是单侧全绿、只有两侧对比时才红。
- **v0.1.10**：更正记录必须回到一手来源重新取证；有时正确的冻结方式是"不冻"；新增浏览器进程组回收——**残留的实例会让像素比对的容差被悄悄放宽**。
- **v0.1.11**：噪声基线必须**两侧各测一遍**；除了"哪些输入会变"，还需要一份"这一帧上哪些东西会上色"的清单；同一个答案在工具链里只能有一份实现。

### 版权取证与镜像真实性（v0.1.12 – v0.1.16）

这一段最重要的一条是**推翻了自己上一版的设计**：版权判断归用户，且**版权考量永不削减镜像完整性**。

- **v0.1.12**：版权取证层重写——逐资产表新增"第三方权利人"列；公共领域**必须逐位具名作者判定**（41 位艺术家，在第 41 个名字上被证伪）。
- **v0.1.13**：修上一版的设计错误——**版权判断归用户**，且**版权考量永不削减镜像完整性**（曾以"反正不公开"为由少抓约 60% 资产，而验收全程显示通过）。
- **v0.1.14**：新增**真实性检查**——一个 HTTP 200 不等于"你拿到了那个资源"（镜像里躺着 43 份机器人挑战页，而校验和完全吻合）。
- **v0.1.15**：补齐站点规则文件的**读法**——`robots.txt` 是逐路径的许可声明而非全站开关，禁令要按行为类别归类，**"读不懂"不等于"禁止"**。
- **v0.1.16**：命中次数管的是"这条改动还有靶子"，不是"它达成了目的"；新增两条"静默不结束"的健壮性修复。

### 三次无人值守实测，三次被打回（v0.1.17 – v0.1.23）

每次换一种站点形态跑全流程、全程不介入，把 agent 卡住或蒙混过去的地方补成工具或纪律。

- **v0.1.17**：**第一次全程无人介入实测**，改掉 12 处——判级树判不了最典型的纯 GSAP 站；补齐三件"有纪律却没有工具"的检查；确立**一道检查不能引用生产它所审计之物的代码**。
- **v0.1.18**：**第二次实测（换成 SSG 形态）**——爬虫会静默丢弃白名单外的主机（827 条引用）、引用提取看不见写在代码字符串里的路径（Service Worker 整类隐形）、补漏参数会截短账本。
- **v0.1.19**：URL 本地化只认五种写法，而页面数据块用的是第六种——**540 条潜在外联藏在一次"通过"的检查后面**；新增数据块专用比对。
- **v0.1.20**：**第三次实测（自研引擎站）**——源站代码会按自己的域名分支，而本地化只能改写字面量、改不了那个判断条件。
- **v0.1.21**：像素比对新增**非空画面前置条件**——两张空白截图比出来的"完美一致"，和真正复刻成功长得一模一样。
- **v0.1.22**：上一条的根因是**驱动时机**——冻结后的页面仍在真实时间里等待资源，驱动必须与真实时间交错，否则引擎永远等不到"资源已就绪"的那一帧。
- **v0.1.23**：一个复刻站三条路由做到跨侧 **0.00**——全部残差追到**一行被误判成第三方库的站点代码**。

### 新增源码化阶段，并在两个项目上跑通（v0.1.24 – v0.1.31）

此前流水线停在“已证明正确、但人读不了”。产物改为三段：只读证据 → 逐字移植 → 人写的源码。

- **v0.1.24**：新增**源码化**阶段。此前流水线停在"已证明正确、但人读不了"——14,271 行挤在一个文件里、`e` 出现 2962 次、注释占 0.2%。产物改为三段：只读证据 → 逐字移植 → 人写的源码。
- **v0.1.25**：拆分粒度**不是自由选择**。扁平脚本的声明顺序就是求值顺序，三条硬约束决定了能拆多细；而最"响"的那一条（模块导入的绑定不能被赋值）只有真去构建才会暴露——**它最晚被发现，却最该最早被想到**。
- **v0.1.26**：**推翻上一版的结论**。上一版写着"这个引擎拆不了更细"，两次判为结构性不可能，两次真凶都是自己工具里的一行 bug。线索一直摆着：**一个不随你的修复而变化的指标，说明你没在修真正的东西**。
- **v0.1.27**：作用域安全的重命名有四个坑，**四个都是"构建通过、运行时才炸"**；另修一处已发布检查工具里的字典查找 bug——它会在任何声明了 `toString` 的代码库上误报。
- **v0.1.28**：自包含必须**在仓库外证明**——复制出去、断网安装、构建，然后**真跑起来再对拍一次**。同一份产物"能构建"的时候，其实根本无法验证：验证钩子没跟着走。**交付物要自带它的验证钩子。**
- **v0.1.29**：人工抽查 425 个"有证据"的变量名，找出三类**假陈述**——累加器被命名成下标、矩形被断言成向量、顶层循环的计数器叫 `j`。它们**全部通过了逐像素 0.00**：这是自动检查永远抓不到的唯一一类错。
- **v0.1.30**：源码化在**第二个项目**上跑，五条假设被打破——最贵的一条是"命令记在 shell 历史里就够了"：一次构建的复现只能靠**逐字节比对产物**倒推回去，线索是 11 个字节。
- **v0.1.31**：源码化在第二个项目上端到端完成（921 个模块、中位数 19 行、199 MB 自包含交付物）。同时发现一次**记录在案的绿灯已经过期**——门自上次跑过之后，它审计的东西被重新生成了。

### 第一个模块化打包目标：竖切与逐字移植（v0.1.32 – v0.1.39）

前几个目标都是扁平拼接，这次是 webpack 模块容器——边界由打包器给定，问题整体换了形状。

- **v0.1.32**：一个大型商业站暴露三处镜像缺陷。其中一处的根因是**词法分析器被一个含引号的正则字面量带偏了 16,177 行**；确认修复靠的是一个**外部不变量**，而不是"看起来对了"。
- **v0.1.33**：**打包形态决定工具链**。前几个目标都是扁平拼接，这次是 webpack 模块容器——竖切边界不再由行号猜，而由打包器给定；认不出容器一律 FATAL，不许退回扁平分层表。
- **v0.1.34**：**计数只能找到候选，不能给出答案。** 关键词计数把一个签名行为定位到了错误的模块，而**推翻它的证据就印在同一行里**——另一列是 0。
- **v0.1.35**：编排本身可以是一门语言（每个关键帧的起止是一个表达式字符串）。另：**输出里被截断的 id 会作为输入回来**——静默过滤掉它会产出一个"小一号但看似合理"的切片。
- **v0.1.36**：**一套用例可以全部落在同一条代码路径上并全绿。** 六个用例、六个绿灯、一条曲线——因为把缓动权重当成了曲线名。
- **v0.1.37**：把用例**并排打印**当场抓到两个"绿色的假通过"：一条什么都没写，一条与线性完全相同。
- **v0.1.38**：**门报出一个你没预期的数时，先假设你错了。** 一次手算与引擎的分歧，最后是引擎对——分母是可滚动距离。
- **v0.1.39**：「缺一个前置动作」和「移植错了」表象完全相同，一次竖切里出现三次。三次的解法都是同一个动作：**读源站真实调用点的调用序**。

### 跨侧门与“采来的”用例（v0.1.40 – v0.1.45）

一道门只跑一侧就不是判决。这一段建起两侧同时测量的门，并把用例从手写改成**从源站活引擎里采**。

- **v0.1.40**：第一道**跨侧门**（同一份输入同时喂两侧）。第一次运行三条红，**没有一条是移植缺陷**——一次是门把同一侧量了两遍（这种错会报告**完美一致**），一次是一侧缺前置动作，一次是两侧**测量条件**不同而非行为不同。门因此分成"必须相同"和"只打印"两组用例，并每次自证它量的是两侧。
- **v0.1.41**：模块化打包的目标上，源码化的难点从"切在哪"整体平移到"叫什么"——id 是内容哈希。四个提名想法被数据推翻（按行号重切文本、正则普查、拿报错前几个词、按类型名频次投票），而**最强的证据在模块外面**：属性名不被压缩，一行 `this._chapterPlayer = new M(...)` 能给一个匿名类命名。
- **v0.1.42**：零依赖纪律**按阶段划**——源码化之前整条流水线不装任何东西。一个 M1 阶段的工具违反了它整整八个版本没人发现，而禁止它的原话就写在同一份文档上方三行：**只写在文档里、没有东西去查的规矩会安静失效**。改零依赖的过程中掉出三个既有缺陷，其中一个是所有文档都写着 597 个模块，而真实数字是 569——打包容器里**同一个 id 可以被定义多次**，甚至实现不同。
- **v0.1.43**：一道记录在案的绿门重跑变红，两层原因都不是被测对象变了：那次绿灯**带着一个只存在于 shell 调用里的参数**，后来把命令登记下来时凭记忆重建、参数漏了；而豁免清单本身也过期了——爬虫补上一个作用域漏洞后镜像长大，**绿灯的记录早于产生那条引用的页面**。结论：**判决包含它的调用方式与豁免清单，两者都必须住在仓库里。**
- **v0.1.44**：门的用例应该**从源站的活引擎里采**，而不是手写。采的过程中发现自己的枚举方式漏了 **95% 的被测对象**——声明式属性给概念命名，但引擎用来记"谁参与了"的那个标记才是索引；而当时所有检查依然全绿。另外两条：**「有东西动了」不等于「我要测的那个量动了」**；源站的缓动函数全是匿名的，所以**身份要按行为认**——按取值采样匹配，反而把名字找了回来。
- **v0.1.45**：工具链会**静默截断**结果——探针的 JSON 被砍在 64 KiB 整，因为进程在 stdout flush 完之前就退出了。危险的不是它出错，而是**截断出来的东西看起来是合法的**：断在元素边界上就能解析成功，而记录少了一半、毫无征兆。判据是喂一个已知长度的载荷、量回来多少字节。

- **v0.1.46**：一次整页移植做到 **9 个检查点逐像素全零**，随后的清单式核对发现它**少了两个模块**——一处**条件 require**（`require(cond ? "a" : "b")`）没产生依赖边，而那条分支在被驱动到的路径上不会走到。**逐像素 0.00 不是覆盖率的证明。** 另外三条：自包含要按**账本**复制而不是按文档引用（第一次"能构建"的副本有 17 条报错）；**验证钩子走一半等于没走**；等价门用文本捷径就会测到自己的捷径。

- **v0.1.47**：工具认第二种模块容器（Turbopack）。⛔ 更要紧的是加了一条**合理性判据**：光有"认不出就报错"不够——读错容器时它会**"成功"**，对一个真有 20 个模块工厂的文件报了 2 个模块并打印愉快的摘要。现在"认出来的东西必须解释得了这个文件"。
- **v0.1.48**：**冻结 JS 时钟冻不住 CSS 动画**——`animation` 跑在浏览器自己的时间线上。症状很反直觉：**同侧对照比跨侧还大**，且残差在两次运行之间换位置。两条证据都说明残差不可归因于移植，而正确的读法不是"复刻得好"，是**这道门在这个目标上带宽受限**。

- **v0.1.49**：**模块 id 的类型是容器契约的一部分。** 源码化发射器把 id 写成了字符串而容器要数字，页面渲染成空白——**而所有静态门全绿**（它们查的是内容，不是容器键的类型）。唯一说话的是巡航门的**非空画面前置条件**：它拒绝在空帧上给出比较结果。⚠ 同一目标上还有两个发射器对同一件事给了不同答案。

- **v0.1.50**：**一道检查必须报出它查了多少,否则它的沉默什么都不是。** 冷头清点在新的打包形态上报了绿灯——而它**一个模块都没查**(签名判据只认另一种打包器)。修成"仅 0 时报错"之后,它在**查了 1/20** 时又报了绿。判据得是**覆盖率**,不是"有没有查":凡是逐对象遍历的检查,输出里都要有 `n/N examined`。

## 下一步

- **v0.2+**：补齐剩余的 B 类场景——第三方存储桶资产发现、运行时接口与 headless CMS 快照、超大型多分包代码切片、失效站点的存档抢救。
- **源码化的两块空白**：命名的还原率取决于代码本身留下多少线索——实测一个扁平站有 63% 的局部变量没有任何可依据的证据，一个模块化站有 27/46 个模块只能保留哈希 id。这不是欠账，**错名比哈希更糟，因为哈希会让人去看**。另一块是模块头目前只写事实与溯源，**"这个模块是干什么的"仍然需要人来写**——工具写不出，而写错比留白更糟。
- **远期**：C 类（声明式架构）的"重构式逆向"方法论。实测显示不少大厂创意页正在往这个形态漂移，这条分支迟早要做。
