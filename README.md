# website-rebuild-skill

一个网站复刻技能（skill）：输入一个你想要复刻的网址，按取证式方法论完成 1:1 工程化复刻。

遵循 [Agent Skills 开放规范](https://agentskills.io/)，为**任何支持 skills 的智能体**设计——Claude Code / Claude Desktop 只是其中之一，任何实现该规范的 agent runtime 均可加载使用（skill 内的提问、脚本调用均按运行时能力自适应，不绑定特定产品）。

## 关于网站分类和边界判定

复刻能不能做，取决于一件事：**这个站的"签名行为"（那些让它值得被复刻的动画与交互）住在哪里，以及有什么挡在前面。** 按这条轴，实测把网站分成五类：

| 类 | 名称 | 签名行为住在哪 | 结论 |
|---|---|---|---|
| **A** | **客户端行为站** | 全部在客户端静态资产里，且是**命令式**代码（可逐行转写） | ✅ **主场**，直接开工 |
| **B** | **平台包裹站** | 也在客户端，但外面**裹着一层**必须先剥掉或先快照的东西（平台层、序列化 payload、运行时数据面、第三方资产桶） | ⚠️ **有条件支持**，先剥层再进主线 |
| **C** | **声明式架构站** | 在**声明式组件树/时间轴数据**里（RSC flight 流、R3F + Theatre） | ❌ 转写式移植失效 |
| **D** | **服务端行为站** | 在**服务端**（CMS、购物车/库存、A/B 分桶、个性化注水） | ❌ 客户端无可移植目标 |
| **X** | **已消失的站** | 不存在了（域名易主、平台回收、原地替换） | ❌ 无镜像对象 |

**判级是二维的，不是看框架名。** 「用了 Vue/Nuxt/React 就是 C 类」被实测证伪：判 C 的真因是**引擎范式**（声明式），不是框架。所以要分开问两件事——① **框架模式**：它下不下发行为源？② **引擎范式**：下发的东西是命令式还是声明式？两者都过关才是 A/B。

技能会在第 0 步做指纹侦察并给出判级，超范围会明确拒绝并解释原因，**不会硬跑产出垃圾**。判定树见 [scope-and-fingerprint.md](skills/website-rebuild/references/scope-and-fingerprint.md)。

## 能做什么（A / B 类，均为实测跑通）

| 场景 | 覆盖情况 | 实测样本 |
|---|---|---|
| **命令式 WebGL / Canvas 场景** | three.js、自研引擎、GLSL/TSL 逐字提取 | 自研引擎站（1.25 MB 单 bundle、156 个 shader，三路由跨侧 0.00）、47,224 行 three 引擎单页 |
| **GSAP 时间轴 / 滚动叙事** | 时间轴、ScrollTrigger、自研输入状态机 | 多个获奖作品集站、日文企业周年微站 |
| **烘焙动画与私有二进制格式** | GLB / `.buf` / `.riv` / KTX2，反解为数值账本 | 53 个 `.buf` 几何（170,289 顶点，格式从 bundle 逆出、四项数值断言全绿） |
| **静态构建器产物** | Astro / Nuxt SSG / Webflow 导出壳 / Vite / webpack | Astro 单页、Nuxt 2 SSG（payload 8.9× 展开）、Webflow 导出站 |
| **各种 bundle 形态** | minified / 混淆 / 未混淆均可（行号坐标系 · sourcemap 直取 · 内容哈希坐标） | 全混淆 47k 行、未混淆 974 行、无 bundle 的 Liquid 内联块站 |
| **B 类：平台层剥离** | Shopify（四层模型：平台 / 应用 / 上游主题 / 站点自研） | 两个 Shopify 店铺，其一是 Dawn 主题的 fork 定制店 |
| **B 类：序列化 payload 展开** | Nuxt `window.__NUXT__` / `__NUXT_DATA__` 等 SSG 数据块 | 63.5 KB payload（占文档 54%）展开为 566 KB 结构化数据并逐叶路径对拍 |

实测参照：31 个历年 Awwwards 年度站中，存活可探测的站点全部落在本方法论适用范围内（A/B/C 三级，**无一 D 级**）。

## 不能做什么（明确边界，实测得出）

| 类 | 类型 | 原因 |
|---|---|---|
| **C** | 声明式架构站 | 签名行为在 React RSC flight 流 / R3F+Theatre 组件树里，**"转写式移植"失效**——它需要的是另一套"重构式逆向"（roadmap 中） |
| **D** | 服务端行为站 | 行为主体在服务端（CMS、电商 cart/库存、A/B 分桶、个性化），**客户端没有可移植的目标**，且确定性验收无基准 |
| **X** | 已消失的站 | 无镜像对象。历年获奖站实测消失率约 **29%**（域名易主 / 平台回收 / 原地替换）——这也是"第一时间镜像"成为第一纪律的原因 |

三类各自的实测样本见下文「[本skill已验证过的网站](#本skill已验证过的网站)」。

**注意**：能不能做和该不该公开是两回事。本 skill 定位学习用途，产出默认私有部署 + noindex（这是**安全默认动作**，不是 agent 的法务结论）；公开前必须完成逐资产版权**取证**，**决定权在你**——skill 只负责取证、列选项与风险边界、给建议，"能不能公开/部署/再分发"一律显式交回用户（详见 skill 内 legal-and-deploy 指南）。

## 安装与使用

前提：Node 22+、本机 Chrome/Chromium（无头对拍用）、`npx` 可用。

把 `skills/website-rebuild/` 整个目录放到你的 agent 的 skills 目录即可。以 Claude Code 为例：

```bash
# 用户级（或项目级 .claude/skills/）
cp -R skills/website-rebuild ~/.claude/skills/website-rebuild
```

其他支持 Agent Skills 规范的 runtime 按其各自的 skills 目录约定放置同一目录。

使用：给你的 agent 一个网址，说"复刻这个站"/"1:1 rebuild 这个网站"。技能会自动走：指纹判级 → 开工评级与范围确认 → 镜像取证（⛔ 门）→ 逆向建坐标系（⛔ 门）→ 溯源移植 → 量化验收 → 冷头评审与版权取证（是否公开由你决定）。

## 方法论一页纸

四阶段管线：**镜像取证**（第一时间全站镜像作只读证据，断网跑通为验收门）→ **逆向建坐标系**（js-beautify 钉版本展开，行号是全项目唯一溯源坐标系，逆向笔记先于任何代码）→ **严格溯源移植**（每个改动先找到 bundle 归属行号；bug 与怪写法照抄不修）→ **验证收口**（五类量化验收门按站点特性选型，冷头评审兜底）。

六条宪法：镜像神圣不可污染；源码唯一裁决不凭观感修；源站有的都要有、没有的不做；bug 照抄不修；偏差必须登记（没登记的差异一律视为 bug）；代码与文档同 commit。

## Roadmap

每完成一个复刻项目，就把该轮的新经验合并回本 skill。下面每条是一次版本回流的一句话摘要。

- **v0.1.0**：首个版本——四阶段管线 + 六条宪法 + 判级门，方法论提炼自六个连续复刻项目，适用边界经 43 站实测校准。
- **v0.1.1**：首个实战项目（Shopify 店铺）的回流——新增 Shopify 平台层指南与 HLS 流媒体阶梯补录，修爬虫协议相对 URL 与零外联门断言面。
- **v0.1.2**：WebGL 单页项目 M0/M1——新增场景图数值门、能力探测冻结协议、镜像闭包校验，判定树升级为「框架模式 × 引擎范式」二维。
- **v0.1.3**：发现**冻结的盲区**——被冻分支上挂着的子系统会以"通过"的形式从验收门里消失；配套打包字节切片移植工具。
- **v0.1.4**：发现**快门速度**——单次截图耗时与被测运动全长之比 ≥ ~1/10 时，仪器会造出稳定可复现的假相位差。
- **v0.1.5**：该 WebGL 单页项目收官——三条互证的门失效模式（检查点有位置×状态两维 / 冷头评审粒度 / 扣掉差异区域即掩盖缺陷），并把调试端口改为确定性分配。
- **v0.1.6**：新增 `verify-mirror`——查询参数化的图片 CDN 会让三份不同字节坍缩成一个文件，而零 404 门照样在错镜像上变绿；Shopify 分层三层升四层。
- **v0.1.7**：「零变换即 throw」在高频变换站上恒绿等于没有，改为**逐条变换各带命中次数下限**；零外联断言面补「转义绝对写法」一格。
- **v0.1.8**：期望值必须让引擎往返一遍再取；残差归因前先修仪器；确立分诊信号——**镜像侧红 = 门错，复刻侧红 = 代码错**。
- **v0.1.9**：登记表复核改为阶段固定动作；新增第十种门失效模式**「记录量里混进了时钟」**（单侧全绿、只有跨侧对拍才红）。
- **v0.1.10**：更正登记必须回一手来源；冻结的正确答案有时是"不冻这一条"；新增进程组收割——**残留的浏览器实例会抬高自比带宽，等于让像素门变松**。
- **v0.1.11**：自比带宽必须**两侧各建**（参照侧可能系统性更幸运）；熵源清单之外还需一张"输出侧账"；验收工具链里同一个答案只能有一份实现。
- **v0.1.12**：法务层重写——逐资产表新增「第三方权利人」列，公共领域**必须逐位具名作者判**（41 位艺术家在第 41 个名字上被证伪）。
- **v0.1.13**：修上一版的设计错误——**法务判断归用户**，且**法务考量永不削减镜像完整性**（实证：曾以"反正不公开"为由少抓约 60% 资产，而五道门全程绿）。
- **v0.1.14**：新增 **AUTHENTICITY 门**——一个 HTTP 200 不是"你拿到了那个资源"的证据（镜像里躺着 43 份 bot 挑战页，而账本 sha256 完全吻合）。
- **v0.1.15**：补齐站点策略文件的**读法**——robots 是逐路径许可声明而非全站开关，禁令按行为类别归类，**"读不懂"不等于"禁止"**。
- **v0.1.16**：命中下限管的是"变换还活着"，不是"它达成了目的"；第十种失效模式再添一例（环境扰动作显影剂）；两条"静默不结束"的健壮性缺陷。
- **v0.1.17**：**第一次无人介入实测**（12 条）——判定树判不了最典型的纯 GSAP 站；补齐三件"有纪律没仪器"的工具；确立**一道门不能 import 生产它所审计之物**。
- **v0.1.18**：**第二次实测·换形态**（Nuxt SSG）——爬虫静默丢弃白名单外主机（827 条引用）、提取器看不见 JS 里的字符串路径（service worker 整类隐形）、`--seeds` 会截短账本。
- **v0.1.19**：本地化只认五种 URL 写法而序列化 payload 用的是第六种（`\u002F` 转义）——**540 条潜伏外联藏在一次绿探针后面**；新增 SSG payload 门。
- **v0.1.20**：**第三次实测**（1.25 MB 自研引擎）——源程序按自己的域名分支，而本地化只能改写字面量、改不了那个条件；连续斜杠的归一化发生在了错误的层。
- **v0.1.21**：像素门新增**非空帧前置条件**——两张空帧对拍会报出与完美收官同形的 `meanAbsDiff 0`。
- **v0.1.22**：上一条的根因是**泵的时机**——冻结页仍在真实时间里等资产，泵必须与真实时间交错，否则引擎永远拿不到"资产已到达"的那一帧。
- **v0.1.23**：自研引擎项目收口，三路由跨侧 **0.00**——全部残差追到**一行被 vendor 区间吞掉的顶层裸语句**（`ColorManagement.enabled = !1`）。

**下一步**

- **v0.2+（剩余 B 类缺口）**：第三方存储桶 / manifest 驱动的资产发现、运行时 API 与 headless CMS 快照、多 chunk 大型 bundle 切片、Wayback 抢救流程。
- **远期（C 类分支）**：声明式架构的"重构式逆向"方法论——实测显示大厂创意页正在向该形态漂移（同一系列的三代页面 B→B→C），这条分支迟早需要。
