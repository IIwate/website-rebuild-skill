# 从 Wayback Machine 恢复历史版本

用于目标版本已失效的 X 类项目. `wayback-mirror.mjs` 生成与常规镜像相同的路径映射和资源清单, 另记录捕获时间、CDX digest 和缺失项. 可恢复深度取决于实际存档覆盖, 不能由根页是否存在推断.

first-launch.com 的 2013 年版本曾在存档镜像上完成外壳、资源、数值、像素与自包含检查. 记录包含 32 个检查点、146 个选择器和累计 9,856 个数值样本. 这说明完整存档可以支持 L3, 不说明任意存档都具备同等覆盖. 案例见 [case-studies/archival-rescue.md](case-studies/archival-rescue.md).

## 0. 捕获选择

使用 `id_` 回放形式获取未经 Wayback 页面工具条和 URL 重写处理的响应. 仍须检查响应状态、Content-Type 和内容, 因为存档可能包含原站错误页或挑战页.

`--anchor` 与 `--window-days` 用于逐 URL 选择窗口内接近锚点的捕获. 自动锚点只是候选, 需要结合目标版本核对. 时间接近不保证所有文件来自同一次部署, 应保留每个文件的捕获时间.

`wayback-holes.txt` 记录已发现但未获得的资源. 可交给 `verify-mirror --allow-missing`, 但通过结果必须同时报告豁免项. 当前存档未命中不等于资源永久不可恢复.

## 1. 别名回填

脚本会查找窗口内 basename 相同的捕获, 并可能将其保存到被引用路径. 这种回填依赖"同名文件是同一资源"的推断, 必须检查内容、类型和引用上下文. `FILLED BY ALIAS`、`aliasOf` 与 `referencedAs`/`archivedAs` 用于保留该推断及实际来源.

## 1.5 原域与恢复镜像隔离

原域可能已经返回停放页或新站. 不应把当前原域的爬取输出写入恢复镜像目录. 补充资源使用存档种子或单独目录, 核对版本后再纳入清单. 当前 CDN 上仍可下载的文件也不必然是历史版本.

## 1.6 版本变迁与停放页识别

CDX 中多个无关路径返回相同 HTML digest、根页内容突变或目标资源变成停放页, 都是版本失效线索. `.well-known/*`、`ads.txt` 等路径返回 HTML 不是单独充分条件, 也可能来自 catch-all 路由. 结合捕获正文、时间和已知页面身份判断.

同 digest 可以支持内容相同的判断, 不能单独说明内容属于哪个版本. firstlaunch 的停放页识别记录见案例 §1.6.

## 1.7 锚点与窗口调整

个别资源可能只有较早或较晚的捕获. 调整窗口或为种子指定范围前, 核对它与目标页面的引用关系. 将跨时期资源记录为有意偏差, 不把调整锚点本身当作版本一致性证明.

## 1.8 字体的两级引用

Google Fonts 通常由 CSS 引用字体文件. 先恢复 CSS, 再提取并恢复 `fonts.gstatic.com` 的文件. CSS 可能按 UA 返回不同格式; 使用与恢复环境匹配的捕获, 记录来源, 不根据 digest 变化直接判断错误或任意选择.

## 1.9 按资源层评估覆盖

不能假定存档爬虫执行了页面所需的全部 JavaScript. 对运行时拼接、加载清单和第三方资源, 从已有代码推导 URL, 再查询 CDX 并与镜像核对.

CDX 空结果只表示该次查询未返回捕获. 在据此判定缺失前, 核对协议、主机别名、路径、时间过滤和结果截断. `collapse=urlkey` 用于按 URL 去重, 不自动保证查询覆盖了所有年代和来源.

分别报告代码、媒体、字体和数据的已知总数与已获取数. mustachelab 的记录中, 160 个资产有 157 个在查询范围内无捕获, 虽有代码仍无法离线渲染. 静态引用提取可能漏掉这类资源, 需要把代码推导的清单并入缺失记录.

其他存档和作者提供的副本可作为恢复线索. CAPTCHA、登录或其他访问限制不能由本流程绕过; 联系作者属于需要用户授权的外部沟通.

## 2. 请求频率与失败处理

脚本默认 2 workers、请求间隔 350 ms, 对 429/503 使用退避重试. 这些是实现默认值, 不是目标服务承诺的允许频率. 依据实际限制降低频率; 持续失败时保存进度与缺失记录, 不无界重试.

## 3. 验证语义

资源映射、清单一致性、内容类型、外壳、加载和像素检查仍适用. 以当前原域作 `--resample` 不能验证历史版本, 历史来源应引用 `wayback-provenance.json` 和对应捕获.

验证结果分别说明原路径捕获、别名推断、跨版本补充和未获取资源. 未捕获的 API、POST 响应与外部资源保持未恢复状态.

## 4. 资产许可

站点失效不自动改变内容的版权或许可. 按实际采集与使用范围处理, 见 `legal-and-deploy.md`.

## 4.5 加载失败与缺失记录

恢复完整的路由要求加载检查通过. 已知缺失资源会使浏览器报告失败时, 逐 URL 与缺失记录核对, 报告"有已登记缺失"及其影响, 不称为零错误.

`probe.mjs` 与 `sweep-routes.mjs` 没有 `--allow-404 <holes>` 参数. 相关匹配需由调用方处理. 存档中的 404 响应可作为源站当时行为的证据, 应与"未取得捕获"区分.

## 5. 执行顺序

确认目标版本与分层覆盖, 选择锚点和时间窗, 生成镜像与来源清单, 核对资源和缺失项, 再建立本地运行基线. 后续移植依据该基线进行, 交付时说明恢复范围、版本混合和未恢复内容.
