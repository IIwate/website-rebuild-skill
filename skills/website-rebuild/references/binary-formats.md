# 二进制资产与解码逻辑

用于 GLB、Rive、自定义 `.buf`、SOG、VAT 等数据资产的读取与集成. 先判断是否需要重新实现解码器, 再选择验证方式. 案例见 [case-studies/binary-formats.md](case-studies/binary-formats.md).

## 0. 选择最小恢复路径

优先使用已采集原件与匹配的播放器. 已有解码逻辑可获得时按其行为移植; 必须独立实现时才推导格式. npm 同名库不必然等同于源站 vendored 版本, 替换前检查版本与使用接口.

## 1. 判断依据

确认文件容器与实际载荷、消费它的代码、需要恢复的能力. 已有标准格式或开源参照可作为验证依据, 但先核对版本与扩展. 解码器可能在主 bundle、worker 或 WASM 中, 静态镜像可能漏采运行时引用.

`.riv` 可使用对应播放器; `.sog` 可对照相应版本的 PlayCanvas SOG; 自定义 `.buf` 可从消费端恢复布局; GLB 时间线可导出数值而保留原文件播放. 相关案例见 §1.

## 2. 自定义格式的实现与验证

从读取代码推导头部、端序、偏移、长度、量化公式和引用关系. 将事实与推断分开记录. 实现时校验边界、数量和不支持的特征, 不能在输入不受支持时输出看似有效的数据.

使用独立样本或参照实现验证解码值, 再检查运行时绑定. 全量文件可解析只证明未发生解析失败, 不证明字段与渲染正确. oryzo 的 `.buf` 记录包含 25/25 解析成功及 `/debug/buf` 调试页; 专用页面按实际诊断需要采用, 不要求每个格式都新增路由.

源站中的 `mipFilter` 和 `format="R8"` 等异常实现是否需要保留, 取决于它是否影响目标行为. 工具自己的边界检查与错误处理不属于需要照搬的源站缺陷.

## 3. GLB 动画

`scripts/dump-timelines.mjs` 从支持的 GLB accessor 中导出时间、分量、插值与数值. 按脚本的格式边界使用, 不将它当作完整 glTF 加载器.

noomo 将时间线导出为 JSON, 比较 t=0/5/10/19 的相机采样, 使用小数点后三位精度. 验证时区分 LINEAR、STEP 和 CUBICSPLINE; 后者输出包含切线与值, 不可按普通关键帧数组解释. 保留原数据文件作为来源, 数值记录用于比较和排障.

## 4. Worker 与烘焙协议

对 VAT 等由 worker 生成的数据, 记录消息类型、缓冲区所有权、TypedArray 布局、初始化条件和回传时序. samsy 将 baker worker 与主 bundle 一并分析, 并保留四套 MSDF 字体 JSON/PNG 及 `msdfunit = 6/图集尺寸` 的用法. 验证覆盖消息与消费结果, 不只验证文件存在.

## 5. 格式参考

| 格式 | 项目 | 恢复与验证 |
|---|---|---|
| Lusion `.buf` | oryzo | 根据解码器移植, 比较量化值与实际渲染 |
| SOG | oryzo | 对照对应开源实现, 检查排序 WASM/worker |
| VAT | samsy | 恢复 worker 协议与状态更新 |
| GLB 时间线 | noomo | 导出采样与插值记录, 比较播放器结果 |
| Rive `.riv` | lando | 匹配 canvas-lite/WASM, 验证集成生命周期 |

## 6. 常见问题

运行时 worker/WASM、模板路径和移动变体可能不在静态发现集合中. oryzo 的 `getMobileUrl` 在扩展名前插入 `_MOBILE`, noomo 的模板路径需要从代码展开. 内联 base64 提取后核对原字节.

保留模型内在 scale 和坐标约定; 不为接入方便任意旋转或归一化. 自写解码工具使用独立输入验证, 避免生产与检查共享同一错误后同时通过. 具体数据与症状见案例 §6.
