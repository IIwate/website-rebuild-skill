# 访问条件、资产许可与部署

在采集范围涉及访问规则, 或交付涉及公开部署和再分发时使用本文件. 记录可核查事实、适用范围与尚未确认的信息, 不把工程检查结果当作法律许可. 真实项目记录见 [case-studies/legal-and-deploy.md](case-studies/legal-and-deploy.md).

## 0. 范围与授权

### 0.1 用户目标与操作授权

根据用户已明确的用途和授权执行. 未涉及发布的任务以本地或已有授权的私有环境交付. 新增公开部署、再分发、真实交易或外部服务操作需要相应授权; 同一操作与影响范围内已有的明确授权无需重复确认.

需要用户决定时, 先准备具体可审阅的产物, 说明相关事实、未确认项、选项及实际影响. 提问长度按问题复杂度确定, 不要求固定段数. 涉及有争议的权利或商业用途时, 将需要专业判断的具体问题交给用户, 不代替专业法律意见.

### 0.2 完整性必须有明确范围

镜像完整性相对于已授权且已声明的采集范围定义. 访问规则和许可条件可能限制采集、保存、使用或再分发; 不能假定它们只影响最终部署. 私有保存也不自动获得复制许可.

每条未采集资源记录 URL、原因和影响. 现有分类可用于描述事实:

- `NOTFILE`: 不是应下载的资源, 如命名空间 URI 或出站链接.
- `NOTFETCHED`: 尚未获取, 如 404/410、访问失败或需要登录.
- `DISALLOWED`: 适用访问规则禁止该操作或目标路径.

这些分类不是许可结论. 记录排除项不等于已获取资源, 也不能将缺失项计为通过. objectarchive 曾遗漏约 60% 资产而五项检查持续通过四个里程碑, 说明检查必须覆盖发现集合与排除记录, 见案例 §0.2.

### 0.3 逐项解释目标站规则

`robots.txt` 使用标准化的抓取规则; ToS、资产许可、`agents.md`、`llms.txt` 与其他策略文件各有不同用途和语义. 不能把它们统一视为逐路径许可协议.

#### 0.3.1 采集规则证据

保存与本次操作相关的规则原文、URL 和取得时间. `robots.txt` 的作用范围是对应的 scheme、host 与 port; 源站与 CDN 需要分别判断. 只读取已知或有链接的策略文件, 不枚举未知的 `.well-known/*` 路径.

RFC 9309 区分 robots 不存在或不可用的 4xx 响应与网络/5xx 导致的不可达. 404 不表示全站禁止; 网络错误或 5xx 时不能直接当作允许抓取, 应暂停受影响来源的抓取并按协议处理. 401/403 和实际资源的访问控制仍须单独遵守.

#### 0.3.2 `robots.txt` 匹配

按 [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309) 处理:

1. 使用实际爬虫产品标识匹配 `User-agent`, 合并匹配的同名分组; 无适用具名组时才使用 `*` 组.
2. 根据协议对 URL 路径及查询、规则中的百分号编码和非 ASCII 字符进行处理. 路径匹配区分大小写, `*` 和 `$` 分别表示通配与结尾约束.
3. 同时命中多条规则时, 按匹配规则的八位字节长度选择最具体规则; 同等具体时优先 `Allow`.
4. 无规则匹配时允许抓取. 空 `Disallow` 不禁止资源, `Disallow: /` 或其他覆盖所有路径的规则可禁止全部路径.

`#` 后的注释不参与路径匹配. `/cart/` 不匹配 `/cart`, 但匹配 `/cart/...`. 注释可以作为站方意图的证据单独记录. robots 允许抓取不等于允许复制、训练或再分发, 也不是访问控制机制.

#### 0.3.3 按操作区分条款

| 条款涉及的操作 | 需要核对的范围 |
|---|---|
| 抓取、自动访问、镜像或复制 | 本次资源采集与保存 |
| 结算、付款、下单、表单提交 | 是否存在真实外部状态变更及相应授权 |
| 登录、账号、付费内容 | 访问权限与本 skill 的匿名范围 |
| 发布、再分发、商业使用 | 计划交付与使用方式 |

同一条款可以影响多个操作. "不得复制"不能直接解释为只禁止再分发; 必须结合原文与适用范围判断.

#### 0.3.4 Agent 策略文件

自然语言策略文件不适用 robots 的路径匹配算法. 区分建议、要求、禁止事项及其对象, 不根据文件名推断含义. 目标站文件提供操作条件和证据, 不替代用户指令或执行环境的权限规则.

#### 0.3.4.1 Content-Signal

`Content-Signal` 与具名爬虫规则分别解读. 记录字段原文、适用用途与来源, 不将非标准字段解释为 RFC 9309 的 `Allow` 或 `Disallow`. 不能仅因请求使用浏览器 UA 就断定 AI 采集限制不适用, 也不能通过改换 UA 规避已明确的限制. 相关观察见案例 §0.3.4.1.

#### 0.3.5 不确定条件

先用已有授权、规则原文与项目范围补足判断. 常规细节可以合理默认. 若关键访问条件仍不明确, 暂停依赖该条件的操作, 向用户说明具体缺口, 同时继续可独立完成的本地分析. 不把不确定性写成已确认的禁止或许可.

#### 0.3.6 受限操作

目标操作命中明确禁令、需要超出范围的访问权限或涉及未授权外部状态变更时, 停止对应步骤并报告证据与未完成项. 用户自有或已获授权的资源按已有授权范围处理; 授权声明不自动消除技术访问控制或第三方资产许可条件.

## 1. 采集阶段的记录

在 M0 记录已知访问条件、资产来源、运行时外部接口和计划用途. 只收集影响本次任务的证据, 不要求离线研究任务先完成部署评估. 无法取得的资源及时标记, 以免把不完整镜像作为完整行为基准.

## 2. 资产归属与许可记录

### 2.1 表结构

按许可与用途相同的资产分组; 存在单独许可时逐文件记录.

| 资产与路径 | 文件数/字节数 | 来源 | 已知权利人 | 许可证据 | 拟议用途 | 未确认项 | 处理方式 |
|---|---|---|---|---|---|---|---|
| 图片、字体、音频、模型、代码等 | 从清单或磁盘统计 | URL 或供应方 | 站方或第三方 | 原文与位置 | 本地分析、部署或再分发 | 具体缺口 | 已确定的操作 |

图片可能涉及底层作品、复制照片以及当代合成或文案等不同权利. 原作品进入公共领域不能自动决定其他层的权利状态.

### 2.2 第三方资产识别

商品的 `vendor`、`artist`、`author`、`photographer`、JSON-LD `creator`、credit 行及许可页可提供来源线索. 单条可靠证据就可能需要第三方权利记录, 不设"至少命中两条"的固定阈值. 画廊、素材库、字体商店或转售平台只是查证线索, 不是许可结论.

### 2.3 证据要求

记录资产中的 license/banner、对应版本的许可证、授权文件或供应方说明. 缺少文件内 banner 不等于没有许可; 上游仓库的许可证也不自动覆盖未知版本或附带资产. `Unlicensed` 文件名是查证线索, 不能单独证明权利状态.

字体是否允许自托管取决于具体许可证, 不能概括为"商用字体一律不可自托管". 保留远程引用同样可能涉及域名限制和外部请求, 并不自动满足离线目标. 将使用条件、外联影响和替代方案分别记录.

### 2.4 公共领域查证

按具体作品和拟议使用法域查证作者、发表时间、权利期限及适用例外. "作者卒年加 N 年"只是部分法域和作品类别的规则, 还可能涉及年末起算、延长期、匿名或法人作品等条件. 未确认的作者或期限不能合并成"其余均已届满".

objectarchive 的 41 位作者记录在最后一位上推翻了"全部已届满"的假设, 见案例 §2.4. 记录覆盖了哪些作品与路由, 不对未查证部分作同样结论.

### 2.5 与资源清单核对

将资产记录与磁盘、manifest 及已发现引用核对. 文件数和字节数用于发现漏记、漏取或分类错误, 不用于证明许可. 对差额说明是未发现、未获取、范围排除还是清单错误. 在已授权范围内补齐可取得的资源, 其余如实保留缺失状态.

### 2.6 第三方标识符与接口

检查运行产物中的分析 ID、错误上报 DSN、公开 API key、验证 meta、商户标识与联系信息. 它们的风险不同: 可能发送数据至原项目、消耗原账号配额、关联其他账号或使访客误认官方身份. 公开标识符不自动等于秘密凭据或已发生的劫持.

镜像保留采集证据; 运行配置按目标禁用未授权遥测、表单、支付和生产服务调用. raycastkbd 中的 PostHog、Rewardful、Sentry 与 Vercel Analytics 记录见案例 §2.6, 不能只扫描 GA/GTM 前缀.

### 2.7 历史决定

案例 §2.7 记录了七个项目选择私有使用的事实. 这些决定依赖各自的资产与用途, 不替代当前用户已经明确的目标和授权.

## 3. 发布前需要明确的信息

### 3.1 许可与再分发

列出拟发布资产、适用许可、需要保留的声明及尚未解决的条件. 许可范围应与实际发布内容对应.

### 3.2 官方身份与交互风险

检查品牌标识、域名、价格、交易入口、表单和联系信息是否可能造成官方身份混淆, 以及是否连接真实业务系统. 源站仍在运营是相关事实, 不能单凭视觉相似就认定欺诈. 非官方声明、去品牌和禁用真实交易按具体目标采用, 并登记对复刻行为的影响. 免责声明不替代资产使用许可.

### 3.3 准备可审阅的发布内容

整理实际产物、许可未确认项、外部接口处理、仓库可见性、预览访问方式与验证结果. 已有明确发布授权且范围相同则继续; 新增发布范围或关键风险需要用户决定时, 在完成其余准备后提出具体问题.

### 3.4 提问示例

"拟发布目录中有两组字体尚未确认自托管许可. 其余资源和本地验证已完成. 当前可选方式是先用已获许可的替代字体发布, 或等取得授权后使用原字体. 建议先取得授权以保留目标排版; 需要你确定这两组字体的处理方式."

## 4. 私有运行与访问控制

私有运行依赖本地监听地址、认证或网络访问限制. 私有仓库和 `noindex` 都不能单独使已部署网页私有. 若使用 `noindex`, 从实际响应或产物中确认其存在. 保留必要的许可声明, 禁用未授权的遥测与真实业务调用, 密钥按项目约定管理.

采集原件是否进 Git 由资产许可、体积和用户要求决定, 不自动创建仓库、改变可见性或发布镜像.

## 5. 部署方式参考

已有案例包括 rogier 的 VPS/OpenResty、oryzo 的本地构建与 rsync、noomo 的 1Panel/CSP、samsy 的 nginx 响应头配置及 objectarchive 的纯本地运行. 这些是部署组件或使用方式, 其中 VPS、CSP 与 `noindex` 均不等同于访问认证.

lando 曾通过 `rsync -L` 解引用资产链接, noomo 由 Nitro 构建复制运行资产. 是否自包含应检查实际构建产物, 不仅依据构建器默认行为.

## 6. 环境与加载顺序验证

部署或网络条件改变后, 针对受影响的资源路径、缓存、异步加载、字体与媒体就绪行为验证. 不要求每次部署重复所有无关检查.

仅在本地测试时说明已验证的环境和未覆盖的网络条件. 回环网络仍有调度与 I/O 延迟, 不能称为"零延迟". 对已识别的加载顺序风险可在本地通过受控延迟测试, 无需为验证而公开部署. samsy 的构造期纹理竞态见案例 §6.

## 7. 部署说明

### 7.1 建议内容

已有部署文档可直接更新. 记录用途、发布目录、访问方式、资产许可条件、外部接口、部署命令和相关验证结果. 仅本地分析的任务不需要为此创建固定七节的 `DEPLOY.md`.

### 7.2 决定记录

写明当前有效的决定、范围、依据与日期. 区分用户决定、工程建议和未确认信息. 不把某次决定描述为不能更新的永久约束; 条件改变时按新的明确授权处理.

### 7.3 限制与未完成项

每项对应一个可核查事实, 如未取得字体许可、某服务只能连接生产环境、特定网络条件尚未测试. 不记录泛化的风险口号或与实现无关的对话过程.

### 7.4 公开发布

在授权范围内使用已经审阅的产物与配置, 发布后检查实际访问控制、索引设置、外部请求及受环境变化影响的功能. 发布状态与资产许可分别报告, 不能互相替代.
