# 版权评估与部署决断

> **何时加载本文件**：两个时点必须加载——M0 镜像阶段做版权预评估时；收官阶段写 DEPLOY.md、做"是否公开部署"决断时。

## 0. 本 skill 的立场（先读这段再往下走）

**本 skill 用于学习目的的复刻。默认产出不公开部署**：私有仓库 + 本地/私有预览是常态终态，六个项目全部如此【oryzo】【samsy】【kimi】【noomo】【lando】。

如果用户明确要求公开部署，必须先完成 §3 的版权决断流程，且公开页面上**显著标注"非官方复刻"与原作者/原站归属**——没有完成决断和标注之前，不执行公开部署。

判断依据是六个项目的一致结论：**"最大风险是法务不是技术"**——oryzo 与 kimi 都把素材版权在难点表里评为 ★★★★★【oryzo】【kimi】，lando 的难度评级同样是"素材版权 ★★★★★ 远大于技术"【lando】。

六个项目的实际决断，作为默认预期：

| 项目 | 决断 | 关键因素 |
|---|---|---|
| rogier | 部署到私人 VPS，部署只上 `dist/` | 【rogier】 |
| oryzo | 仅个人学习研究，不公开部署（README 明确声明） | Adobe Fonts 商用授权、版权风险 ★★★★★【oryzo】 |
| samsy | 私有预览 + nginx `X-Robots-Tag: noindex`，资产不再分发 | 【samsy】 |
| kimi | 仓库私有、仅 noindex 私有预览 | 素材版权归 Moonshot AI，README 开头声明【kimi】 |
| noomo | 不公开部署，私有仓库 + 本地/私有预览为终态 | 模型/音乐/视频/字体/品牌标识均不可再分发【noomo】 |
| lando | 私有仓库、不公开部署 | F1/McLaren/肖像/商标不可再分发【lando】 |

## 1. 时点一：M0 就做版权预评估（不是收官才想）

版权评估要在阶段 0 完成决策，因为**技术方案随之定形**【oryzo】：oryzo 在阶段 0 就定下"不公开部署、授权字体不入库、镜像不再分发"，后续的资产管理与部署方案都是这个决策的推论。kimi 在 README 开头即声明素材版权归 Moonshot AI、镜像保留仅为让逆向结论可复核【kimi】。

**指令**：M0 里程碑日志里必须出现版权预评估条目；把"素材版权"写进难点/风险表并评级【oryzo】【kimi】【lando】。

## 2. 逐资产归属/许可表

收官前产出逐资产的归属/许可/可部署性表格（noomo `DEPLOY.md` §3 是范本）【noomo】。表列结构：

| 资产 | 归属方 | 许可状态 | 可再分发？ | 处置 |
|---|---|---|---|---|
| （逐类填写：模型 / 音乐 / 视频 / 字体 / 品牌标识 / 人物肖像 / 商标…） | | | | 不入库 / 保留原引用 / 私有预览可用 / 禁止公开 |

填表规则：
- **逐资产**而非笼统一句"版权归原站"——每类资产单独一行，归属没查清的标 [未确认] 并**按不可分发处理**；
- 覆盖面别只想着媒体文件：字体授权（商用网页字体不可自托管【oryzo】）、人物肖像与商标【lando】、品牌标识【noomo】都是独立风险项；
- 处置一栏与 asset-management.md 的决策联动：授权字体"保留原引用不入库"【oryzo】【samsy】、镜像副本"仅供逆向复核不再分发"【kimi】。

实例可对照：
- noomo：凤凰模型 / 音乐 / case 视频 / Trial 字体 / 品牌标识均不可再分发 → 结论"不做公开部署"写在 DEPLOY.md 开头，**结论先行**【noomo】；
- lando：F1 / McLaren / 人物肖像 / 商标素材不可再分发，DEPLOY.md 开头明确【lando】；
- oryzo：Adobe Fonts 的 Halyard 商用授权不可自托管 → 保留 Typekit 引用、不入库【oryzo】。

## 3. 公开部署决断流程

按顺序执行，任何一步不通过即落到"私有部署"：

1. **逐资产表完成且无"未确认"项**——归属没查清的资产按不可分发处理。
2. **存在任何不可再分发资产 → 不公开部署**（六项目的实际走向：全部私有）【noomo】【lando】【samsy】。
3. 即使资产全部可分发，公开前还需：显著标注非官方复刻 + 原作者/原站归属；确认不与原站产生混淆（域名、SEO）。
4. 决断结果写进 `DEPLOY.md`，**先出"是否公开"的决断再谈部署方式**【noomo】。

若走到公开部署（罕见路径），追加清单：
- [ ] 页面显著位置标注"非官方复刻 / 学习目的"与原作者、原站链接
- [ ] 逐资产表随仓库公开，作为可审计依据
- [ ] 与原站的偏差表（REBUILD_PLAN §6）保持最新——公开产物的忠实性声明依赖它

## 4. 私有部署检查清单

私有 ≠ 随便部署，六项目沉淀的合规配置逐项照做：

- [ ] 仓库私有【kimi】【lando】
- [ ] 预览站加 `noindex`：samsy 用 nginx `X-Robots-Tag: noindex`【samsy】；kimi 部署仅 noindex 私有预览【kimi】
- [ ] 源站的分析/遥测**不复刻、不上报**：GA 不接入【samsy】；lando 把"遥测不复刻（私有部署不应上报）"登记为偏差 6.1【lando】；noomo 用 CSP 拦截源站 GA 上报【noomo】
- [ ] 镜像不再分发（镜像保留仅为逆向结论可复核）【oryzo】【samsy】【kimi】
- [ ] 第三方实时服务讲礼仪：samsy 的 PartyKit 直连源站生产房间，DEPLOY.md 明确提醒"别广播"【samsy】
- [ ] 部署密钥/脚本不进仓库：oryzo 的 DEPLOY.md 与 deploy.sh 均 gitignore【oryzo】
- [ ] 合规边界从第一天写进 README/DEPLOY，而非事后补【samsy】

## 5. 私有部署方式参考

六个项目实际用过的私有部署形态（供选型，不是必选项）：

- **私人 VPS + OpenResty**：rogier 部署到私人 VPS，部署只上 `dist/` 产物【rogier】；
- **本地 build + rsync 到 VPS（1Panel + OpenResty）**：oryzo 的 `DEPLOY.md`/`scripts/deploy.sh` 均 gitignore，不进仓库【oryzo】；
- **1Panel 私有部署 + CSP**：noomo 的 DEPLOY.md 含具体配置，CSP 拦截源站 GA 上报【noomo】；
- **nginx 加 `X-Robots-Tag: noindex`**：samsy 预览站配置【samsy】；
- **符号链接资产的部署解引用**：lando 用 `rsync -L` 把 `dist/ext → legacy-mirror/assets` 符号链接解成实体文件【lando】；noomo 靠 nitro 构建时自动拷入 `.output/public` 使产物自包含（DEPLOY.md 实测更正过这一点——部署前实测，别想当然）【noomo】。

## 6. 部署即验证

部署不是流程终点之后的杂务，而是**最后一重验证**：真实网络延迟会暴露本地永不触发的竞态【samsy】。

samsy M12 实例：部署后暴露源站永不触发的构造期纹理竞态，用 CDP Fetch 单文件延迟二分定位到两张纹理，根因判定为"部署拓扑差异（单源 vs CDN 分域）"而非代码；修复拆成"保真修正"与"登记偏差"两笔分开处理【samsy】。

**指令**：部署后在真实网络下复跑全部验收门；仅线上出现的问题按 environment-traps.md §3 的流程归因，不许直接改代码糊平。

## 7. DEPLOY.md 产出要求

收官时 `DEPLOY.md` 必须包含：

1. **版权决断结论（放开头）**：是否公开部署及理由【noomo】【lando】；
2. 逐资产归属/许可表（§2 格式）【noomo】；
3. 部署方式与合规配置（noindex、CSP、遥测剥离等，§4 清单的落实记录）【samsy】【noomo】；
4. 部署验证结果（真实网络下的门是否全绿、发现的拓扑差异问题及处置）【samsy】；
5. 若公开：非官方复刻标注与原作者归属的落实位置。
