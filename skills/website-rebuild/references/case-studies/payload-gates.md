> **何时加载本文件**:不在必经集合里. 只在想知道 `payload-gates.md` 某条规则**为什么存在**, 或要核对它的实证强度时读; 章节号与 `payload-gates.md` 一一对应.

## 1. 自带长度的载荷: 改写它, 就得重新声明它

### 1.1 长度前缀的验证

规则见 `payload-gates.md` §1.1.

实测 eightdesign:115 条路由里 **2 条只渲染出 70 个字符**(对侧 2,440).

 而**其它每一道检查都是绿的**:零 404, 零请求失败, 镜像账本自洽, chunk 字节一致,
HTML 尺寸相同. 静态检查看不见它, 因为字节合法; 运行时探针看不见它, 因为没有任何请求失败.

 定位它的动作值得记下来:**拿 `python3 -m http.server` 提供服务同一个目录**.两条路由完美渲染.
一个最朴素的静态服务器和我们的服务器在**同一份字节**上分歧, 就把故障从"字节"钉到了"服务器".
 **手上有两个能做同一件事的实现时, 让它们跑同一份输入, 是最便宜的二分.**

### 1.3 先拿真值校准这道检查

规则见 `payload-gates.md` §1.3.

 这道检查的第一版断言"行的声明长度之后必须是换行",于是把**每一份**文档判为损坏--
**包括源站自己发出的字节**.

 **一道检查判它所审计的源头有罪, 是"错的是检查"这件事最便宜的信号.** 值一次 fetch.
校准之后: 源站 PASS, 镜像原始字节 PASS(828 行/115 页), 服务层输出 PASS,
**port 构建字节 FAIL 17 页**--那 17 页正是构建层的同一个 bug 烤进交付物的地方.

## 2. 文本内容中的 URL[eightdesign]

规则见 `payload-gates.md` §2.

实测:115 条路由里恰好 1 条--一篇讲本站改版的文章, 把它谈论的那个地址印了出来:

```html
<a href="https://host/">https://host/</a>
```

href 必须本地化. 锚**文本**不能: 改了以后页面读作"こちら /",不再指名那个站点.
两侧各自稳定, 相差 25 个字符.

## 4. Flight 载荷的差异分类

规则见 `payload-gates.md` §4.

`verify-payload` 原本只认 Nuxt2/Nuxt3 两种形状--**而野外最常见的序列化载荷是 React flight**,
Next.js App Router 每一页都内联它. 一道为"跨侧比较载荷含义"而存在的检查, 不认识大多数目标的载荷.

### 4.1 判据: 结构必须一致, 每处值差异必须限于一个**引用**

规则见 `payload-gates.md` §4.1.

 归一化写错三次, 每次都把"移植合法做的事"判成内容差异:

| 版本 | 症状 |
|---|---|
| 绝对 URL → `\0URL\0`,本地路径 → `\0PATH\0` | **本地化本身**被判为内容差异(两个占位符就是两个类, 而这里只有一类) |
| 只抹带扩展名的路径 | 无扩展名的路由 URL(`/eight-journal/x`)漏网,115 条里 52 条失败 |
| 不认 `/ext/<host>/` | 桩掉的外部主机全部失败 |

修好后:**115 条路由全部 PASS,609,188 个叶子路径逐一比对.**

## 5.  检查必须可读地失败--顶层 await 里的一次 404 会带走整道检查

`verify-payload` 的 `get()` 在非 2xx 时 throw,而 §5 新增的两次载荷文件抓取**不在任何 try 里**,且这个文件里每一次 await 都是**顶层的**.

 **实测**:B 侧不供 `_payload.json` 时, 检查在第 1 条路由后打出栈追踪, 第 2 条**从未被检查**,总结行也没了. 读起来像"检查坏了",而实际发生的是"这一侧交不出载荷"--这里的区别是: **一个死于异常的检查, 和一个报告失败的检查, 传达的是相反的意思**.

 并且路径是从 **A 侧**推导后套到 B 侧的, 连 buildId 一起套过去. 复刻侧不会有源站的 buildId,于是它**为一个自己提供服务得好好的文件回了 404**.实测: A 在 `/_payload.json`, B 在 `/build-xyz/_payload.json`,修前直接崩, 修后 PASS.

 两条修法: 抓取失败降成 FAIL 一行(**不是抓取失败的异常仍然抛**--吞掉自己 bug 的检查比死掉的更糟);**每一侧问自己的文档**要路径, 两侧形状不一致本身报成一条发现, 而不是伪装成 404.

## 6.  devalue 载荷与 URL 改写边界[hubtown]

规则见 `payload-gates.md` §6.

hubtown 的岛里带着部署站点记录(`"hubtown-live"`,env,url).WebGL 引导从中推导
Theatre 环境; 把那个 url 本地化成 `/` 之后,`new URL(...)` 与 sheet 查找在**三层之外**
炸成 `addSheetObject reading 'object' of undefined`--期间每个请求都是 200.

### 6.1  守卫落在两个本地化实现中的一个, 等于没落

§1.4 已经写死了: 本地化在本工具链里**有两份实现** -- 构建层 `lib/shell-build.mjs` 把它烤进 port 的字节, 服务层 `serve.mjs` 在镜像出检查时改写 -- 而防止两者漂移的约束是"两边必须一致的东西放进 `lib/`,两边 import".§6 的守卫最初只落在构建层.

 **实测**:拿同一份带岛的文档喂给只改了构建层的那版 `serve.mjs`,出检查的字节是

```
[{"url":"/","env":"live"},"/island.png"]
```

-- 正是构建层刚学会不做的那次本地化. 两条后果按 B 侧怎么提供服务二选一,**都是坏的**:

- B 侧也走 `serve.mjs --origin-host`(`determinism.md` 记的双侧同服配置)→ 响应层把构建层刚保住的岛原样改回去,**这个守卫没有任何效果**;
- B 侧直接吃构建字节 → 两侧对同一个字段给出不同答案, 载荷检查的分类器把 `https://host` 与 `/` 读成**内容差异**,于是**检查在这个守卫专检查要保护的站型上失败**.

 判别信号很便宜:**一个只在一侧生效的守卫, 它的证据只会出现在一侧**.修一个两侧事实之前, 先数一遍这件事有几个实现.

### 6.2  整块切除是一笔**交易**,被放过的那一半必须有检查看见

切除保住了应用要解析的字段, 也**连带保住了岛里其它每一条绝对 URL**.而序列化载荷正是本工具链量到过潜伏外链的地方:11 条媒体主机 URL 躲过了其它每一种本地化形状, 运行时探针只抓到 1 条--**载荷里的 URL 不被请求, 直到页面刚好要它**.

 所以"零外联不受影响"是**对某一个站的岛的实测, 不是岛的性质**.切除必须把它保住了什么**交出来**:

- 带扩展名的(按形状就是地址)→ 构建层 `build-site.mjs` **判为失败拒发**,它们是交付物会带出去的外联, 而任何加载期探针都看不见;
- 其余(数据形状)→ 参照服逐条点名一次后继续提供服务(服务器不能 FATAL,但也不许沉默).

## 7. `notice: true` 会变成页面上的文字[raycastkbd]

规则见 `payload-gates.md` §7.

外壳构建器的 noindex 注入写作 `(cfg.notice || "") + '<meta …>'`.
配置里写 `notice: true`(再自然不过的写法),字符串拼接把它渲染成 `<head>` 里的
**裸文本 `true`**--HTML 解析器遇到 head 内文本会**提前闭合 head**,
把后面的 `<meta>`/`<link>` 全搬进 body.

 症状: 导航按钮消失, canvas 不挂载, 页面角落一个 "true".
而**每道静态检查都是绿的**--外壳检查重放的就是变换表自己产出的字节, 长度检查也对.
只有渲染层文本对比抓到了它.
