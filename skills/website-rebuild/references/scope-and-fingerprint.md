# 第 0 步: 范围判定与技术指纹

用于确认目标版本、可获得的实现和可恢复范围. 仓库的 43 站探测记录提供了反例与分类参考, 其中 landonorris、lusion、noomo 是已完成项目的对照样本; 这些样本不构成对所有站点的统计保证. 记录见 [case-studies/scope-and-fingerprint.md](case-studies/scope-and-fingerprint.md).

## 1. 判级体系

| 类别 | 判据 | 后续工作 |
|---|---|---|
| A | 目标行为主要由可获得的客户端代码与静态资产实现 | 常规镜像与移植 |
| B | 客户端行为可获得, 但需平台适配、运行时数据快照或外部资产整理 | 加载相关场景参考, 记录依赖与限制 |
| C1 | 服务端组件源码不可获得, 有 HTML/RSC 输出可作观察基准 | 按 `rsc-reconstruction.md` 从输出重建 |
| C2 | 声明式组件的客户端实现可获得 | 按客户端代码移植, 保留框架运行时约定 |
| D | 请求恢复的能力依赖不可获得的服务端逻辑或私有状态 | 说明该能力的边界, 继续可实现且已明确的部分 |
| X | 目标版本已失效, 需要从存档恢复 | 按 `archival-rescue.md` 评估覆盖 |

同一站点可按能力分层判级. 库名、bundle 数量、文件体积、是否获奖或是否存在 CMS 都不是独立判据.

## 2. 指纹探测流程

`scripts/fingerprint.mjs` 使用 Node 执行 GET、重定向记录、两次响应比较、HTML 指纹与 bundle 初检, 输出 `probe/fingerprint-report.md` 和下载清单. 它收集证据, 不自动判级:

```bash
node scripts/fingerprint.mjs --target https://example.com/awarded-path \
  --bundle https://example.com/assets/main.js --out probe
```

请求遵守已有代理、访问与频率约束. 只进行本地分析时使用已有采集文件, 不执行远程探测.

### 步骤 1: 目标路径与重定向

检查目标路径的 GET 响应、每次重定向和最终页面内容. HEAD 可能与 GET 不同, 不能单独判定作品失效. 根域 200 也不能说明子路径仍可用.

跨域重定向是核对目标身份的线索, 可能是退役、官方迁移、区域站点或访问验证. 确认目标内容是否仍存在后再判 X. 404/410 与网络失败也须分别记录.

### 步骤 2: 两次响应比较

相同请求条件下短间隔采集两次 HTML. 字节相同只说明这两次响应相同, 不证明所有时间、用户或状态确定. 有差异时定位字段:

- nonce、请求 ID 或 WAF token: 先确认其用途, 再决定是否需要规范化或记录.
- 文案、结构、商品数据或个性化状态: 明确快照范围, 评估是否需要服务端行为.
- 挑战页或错误页: 采集失败, 不能当成有效页面的随机差异.

### 步骤 3: 目标版本核对

比较页面结构、资源、generator、依赖版本与目标作品记录. 版权年份较新或技术栈更新只提示版本可能改变, 不能单独证明目标已被替换. 对需要恢复历史版本的任务, 以对应时期的捕获记录为依据.

### 步骤 4: HTML 技术指纹

枚举实际脚本、模块预载、内联 `import()` 与数据载荷, 排除 HTML 注释中的代码. `self.__next_f`、`__NUXT__`、`__NUXT_DATA__`、`__reactRouterContext`、`data-v-*` 是分析入口; 同一页面可以同时含服务端输出与客户端组件实现.

出现次数与匹配行数分别报告:

```bash
rg -o 'self\.__next_f' probe/a.html | wc -l
rg -o 'WebGLRenderer' probe/bundle.js | wc -l
```

字符串命中需要回到应用调用点确认. vendor 内的报错文本或未启用分支不代表站点实际使用了该能力.

### 步骤 5: Bundle 可分析性

检查响应状态、Content-Type、文件内容与源码映射. 极短响应可能是拒绝页, 也可能是合法的小模块, 不按 1 KB 阈值直接判失败. `fingerprint.mjs` 会对小于 1 KB 的响应补 Referer 重试, 其结果仍需检查; landonorris 的 32 字节拒绝页案例说明了这一边界.

有完整 `sourcesContent` 时优先使用公开源码映射. 无需格式化的源文件直接作为坐标基准. 格式化产物保留源文件摘要与工具版本, 校验词法内容, 再针对语义敏感改动验证运行行为.

`/api/` 命中仅提示需要检查请求, 零命中也不能排除接口. 静态扫描不能代替运行时网络记录.

### 计数约束

说明计数对象、文件范围、是否包含 vendor 和采用的工具. `grep -c` 或 `rg -c` 统计匹配行, `-o` 才可逐项输出匹配. `tr ';{}' '\n'` 会修改字符串或正则内部字符, 只能用于临时检索视图, 不可作为源码、token 或行号基准.

### 步骤 6: 行为来源与判级

按 §3、§4 说明行为来源、可用代码、数据依赖和参考状态. 将不确定项单列, 不用类别标签掩盖尚未完成的调查.

## 3. 判定顺序

1. 确认目标版本仍在线还是需要存档, 区分 X 与暂时访问失败.
2. 找到目标视觉与交互的实现入口, 确认哪些在客户端, 哪些依赖服务端.
3. 服务端组件只有输出时标 C1; 客户端声明式组件可获得时标 C2.
4. 不需要额外服务恢复的客户端能力标 A; 需要平台适配或数据快照时标 B.
5. 对无法恢复的服务端能力标 D, 说明与其他可恢复能力的关系.

aimservices 的 `/50th/` 是静态微站, 虽然宿主 robots 含 WordPress 路径, 目标路径的 `wp-content` 为 0, 资产位于 `/50th/assets/`. 应检查目标路径自身, 不能用宿主技术栈代替它.

多 chunk、Rive 数据、GLB、第三方桶、CMS 快照和公开 sourcemap 会改变工具选择或工作量, 不直接否定客户端移植. 相关站点记录包括 stripe 的 74 个分包、chungiyoo、kodeclubs、orano、synchronized-studio 和 persepolis, 见案例 §3.

## 4. 实现来源与运行模式

| 可获得的内容 | 命令式客户端行为 | 声明式客户端行为 |
|---|---|---|
| 客户端实现完整 | A 或 B | C2, 按客户端代码处理 |
| 部分服务端组件只有输出 | 对该部分采用 C1, 客户端部分独立移植 | 同左 |
| 关键服务状态与输出均无法取得 | 对该能力采用 D | 同左 |

### 4.0.1 C1 与 C2

RSC 服务端组件输出不包含原始服务端源码. R3F、Theatre 或 Vue 编译产物则可能包含目标组件与回调的完整客户端实现. `useFrame` 内的数学和状态更新可直接分析, 不因组件写法声明式就归为不可恢复.

eightdesign 的 Next/Turbopack/R3F 案例切片了 18 个模块, 检查到 8 个 canvas, 跨侧指标记录为 99.5%; rauchg 的 C1 案例有 18/18 路由的 Flight 比较记录. 这些结果支持对应样本的可行性, 不代表恢复了原始服务端源码.

判级前回答三个问题:

1. 哪些内容可保存成受控快照, 哪些依赖持续变化的服务状态?
2. 目标视觉和交互由哪些脚本、组件或数据驱动?
3. 可获得的是实现本身、序列化输出, 还是仅有无法复现的远程接口?

## 5. 探测的解释边界

保留 GET 与 HEAD 差异、重定向链、目标路径、挑战响应、内联导入、源码映射和运行时请求的证据. 不从未命中的关键词推导能力不存在, 不把 vendor 字符串作为应用调用次数.

`fingerprint.mjs` 的报告是侦察结果. 镜像阶段有新的请求、路由或资产证据时更新相关结论, 无需重做已确定且未受影响的部分. 具体误判记录见案例 §5.

## 6. 常见误判

- 根域可访问但目标子路径已删除.
- HEAD 返回 404, GET 可获得页面.
- catch-all 路由把 HTML 作为 `.js` 或 `.map` 的 200 响应.
- 库在 bundle 中但未参与目标功能.
- 用 Next、Nuxt 或 WordPress 标签推断所有行为所在层.
- 把两次快照相同或几个关键词未命中当作完整覆盖.

探测样本中约 29% 的目标版本已失效, 包括域名转让、平台回收、域名抢注、路径删除和原地替换. 这是该样本的失效比例, 不是网站的年消失率. 案例见 §6 对应记录.

## 7. 输出

记录目标版本、类别、可恢复能力、依据和未确认项. A/B/C2 进入客户端镜像与移植; C1 使用 RSC 重建参考; X 使用存档参考. D 说明具体能力的限制. 只有关键范围或授权无法合理补足时才询问用户, 并继续独立工作.
