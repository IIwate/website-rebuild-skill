# 验收检查的选择与覆盖

用于为具体变更选择可执行检查. 失败归因见 `gate-failure-modes.md`, 用例与静态覆盖见 `gate-case-design.md`, 序列化数据见 `payload-gates.md`, 确定性驱动见 `determinism.md`. 项目记录见 [case-studies/verification-gates.md](case-studies/verification-gates.md).

## 0. 验证结论的范围

检查应明确输入、前置条件、观察量、通过条件、覆盖数量和失败输出. 通过仅说明这些条件下没有发现违反断言的结果, 不证明所有行为等价. 空输入、两侧连接同一实例或未达到目标状态不能作为通过证据.

按风险选择低成本且有效的检查. 资源与结构问题优先用对应检查定位, 像素与交互验证补充其覆盖. 不要求每个项目、每次提交运行同一套检查或生成固定报告.

### 0.1 期望值与浏览器规范化

比较 CSS、URL 或序列化结果时, 区分源值与浏览器读回值. 必要时把已确认的源值放入独立临时对象, 经同一 API 规范化后作为期望值. 不从被测元素读值再把它作为自己的期望.

```js
const el = document.createElement('div');
el.style.transition = 'filter 1350ms ease, opacity 1350ms ease';
const expectedTransition = el.style.transition;
```

记录源值出处、所用 API 与比较环境. 不同 API 的规范化不同: `new URL()` 不会自动排序查询参数, `el.style.color` 与 `getComputedStyle(el).color` 也不保证同一种表示. 不用一张泛化转换表代替实际 API 语义.

镜像侧失败可能是检查、环境、采集基线或源站自身问题; 复刻侧失败也可能来自相同因素. objectarchive 的 19 次分诊记录是该项目的观察, 不是"镜像失败必然是检查错"的定理.

## 1. 检查类型

### 1.1 HTML、DOM 与载荷比较

有静态或 SSR 输出时, 比较相关 HTML、数据载荷、运行配置、路由状态和重定向. 逐字节、空白规范化和结构比较是不同判据, 应明确采用哪一种.

`scripts/verify-ssr.mjs` 的默认提取器面向 Nuxt, `verify-routes.mjs` 检查路由与 head 字段. 使用前核对页面清单、提取范围与规范化规则. 不能把某个区域字节相同扩展为整个 DOM 或全部运行状态相同.

### 1.2 像素完全一致

在同一浏览器、视口、DPR、字体、媒体和受控状态下比较解码后的像素或读回缓冲区. 相同压缩文件摘要只比较编码输出, 有损 JPEG/WebP 不作为原始像素保真依据.

先用同侧重复采样确认该状态能稳定重现. 同机同版本并不自动保证所有 DOM、GPU 或媒体内容逐像素确定. 非空帧检查也只排除部分无效截图, 仍需确认目标元素与状态确实被渲染.

### 1.3 视觉指标比较

动态场景可比较平均绝对差、网格、亮度剖面或区域指标. 指标、容差、区域和采样协议在比较前确定. `pixelcompare.mjs` 输出像素指标, `pixel-walk.mjs` 按滚动检查点采集, `side-by-side.mjs` 用于人工查看.

#### 1.3.1 位置与状态覆盖

根据内容分段和交互状态选择可达的检查点组合. 关注首尾、关键中段、弹层、模式开关和过渡状态, 不机械执行不可达的完整笛卡尔积.

从更新函数、事件入口与生命周期查找状态转换. 通过源站真实入口驱动, 并检查相应状态量或可见结果. 文件名包含某状态名称不代表已经达到该状态. 未驱动的状态明确列为未覆盖.

#### 1.3.2 重复采样与容差

用相同协议在两侧分别重复采样, 交错运行以减少顺序与负载偏差. 记录每次值与布局、字体、媒体状态, 不只记录最大值. 状态不同的样本不能合并为同一种噪声.

四次独立会话可作为初始调查量, 不是统计充分性保证. 样本数和容差取决于变异程度、错误代价与检查目标. 两侧最大自比差加预定余量是一种工程阈值, 不等同于置信区间或错误率保证.

`pixelcompare --self` 生成单次自比记录. 它不提供汇总多次记录的 `--band` 参数, 项目需根据实测结果设置现有阈值或实现对应比较. 发现采样协议不成立时保留原结果, 修正协议后重新采样, 不通过事后放宽阈值解释已有失败.

### 1.4 数值与状态检查

直接比较相机、uniform、补间、状态机与数据采样值. 优先从独立来源定义期望, 检查实际输出而非仅验证内部标记. mode 字符串可以辅助溯源, 但同一常量同时写在实现和断言里不能证明行为正确.

`verify-tween.mjs`、`verify-harvest.mjs` 和 `verify-crossside.mjs` 需要目标侧接口与配置. 先核对接口返回结构与同步/异步契约, 不将这些脚本当作任意引擎的即插即用验证器.

#### 1.4.1 场景图比较

当场景构建依赖 DOM/CSS 几何时, 可按源站读取逻辑生成对象、矩形、排版和坐标记录. `querySelectorAll`、`getBoundingClientRect` 和 `getComputedStyle` 只是入口线索, 不能单独证明该函数没有其他输入或副作用.

shopifydesign 的 `QL` L30737-L30899 被用于项目专用 `dump-scene-graph.mjs`, 记录 objects、carousels 和 docHeight. 本 skill 不提供该站专用脚本. 比较时按稳定对象 ID 匹配, 保留读取前后的状态调整和作用域.

部分子系统尚未移植时, 根据依赖关系说明哪些字段可比较, 哪些受缺失子系统影响. 不能默认所有几何字段独立于布局. 该项目曾记录 0 blocking / 102 deferred; deferred 项必须有具体原因和后续验证条件.

场景数值一致不能覆盖未执行分支、材质或最终像素. 保留与风险相关的非冻结运行检查, 不把冻结时两侧均未运行视为行为一致.

### 1.5 加载与错误检查

`probe.mjs` 适合单路由诊断, `sweep-routes.mjs` 适合多路由加载. 核对控制台、异常、失败请求及实际订阅的 CDP 域. CLEAN 只描述观察窗口和已监听事件, 不证明没有其他错误.

保存脚本真实退出码. 管道默认可能返回最后一个命令的状态, 使用 `pipefail` 或直接记录检查命令结果. 已登记的例外须随结果说明, 不能把豁免后通过写成零错误.

### 1.6 外部请求与离线条件

区分自动资源请求、预连接/DNS 预取、内联遥测、失败回退、动态拼接及仅用于标识的 URL. `probe --no-external` 检查运行时观察到的请求, `verify-offline.mjs` 对指定页面的响应做静态扫描, 两者都不保证穷尽所有状态和代码路径.

JSON 中的 `https:\/\/`、Unicode 转义和实体需要按其语法解码后检查. 不把命名空间、出站链接与自动请求混为一类. 出站链接通常在激活后才导航, 但框架预取或页面逻辑可能提前访问, 因而不能无条件排除所有 `<a href>`.

报告尚可触发的外联及其条件, 核对实际离线运行. 对未知字符串不得仅按 host 直方图推断已全部处理. 资源存在于磁盘也不说明运行时已引用它.

### 1.7 音频与其他输出

像素检查不能覆盖音频、下载、剪贴板或其他非视觉功能. 对目标范围内的通道确认输入、资源与实际输出. overworldaudio 从 Howler 池枚举 `_src` 并核对 loaded 状态和请求, 见案例 §1.7.

`AudioContext.state === "suspended"` 可能来自自动播放策略. loaded 说明加载状态, 不证明已播放或全部字节来自本地; 本地性还需核对请求来源. 音频播放与用户激活单独验证.

### 1.8 SPA 导航与水合

`assets/templates/verify-spa-navigation.mjs` 根据配置检查客户端导航和直接访问. 每个用例使用独立浏览器上下文, 通过浏览器输入触发导航, 检查目标 URL、容器、文案与不透明度在规定时间内保持, 同时记录页面与网络错误.

稳定窗口只覆盖采样时段, 不能排除任意更晚的重定向或采样间闪烁. 页面正常显示也不能单独证明所有组件已水合; 需要水合证据时增加目标组件的交互用例. lights 的 `/en`、`/fr`、`/about`、`/work` 五个用例是历史项目记录, 不代表模板无需配置即可获得同等覆盖.

## 2. 按风险选择检查

先定位受影响层: 资源与 URL 用清单及引用检查, HTML/载荷用结构或字节比较, 纯计算用数值检查, 导航用浏览器交互, 可见结果用像素与必要的人工观察. 新检查应能区分正常输入与至少一个真实故障反例.

### 2.1 运行与记录

将可重复运行的命令及必要配置留在项目已有位置. 记录覆盖与未完成项. 只运行当前变更相关的检查, 通过后收敛; 新证据影响原结论时再重跑相关部分.

#### 2.1.0 参数与豁免

参数和豁免文件是判据的一部分, 与结果一起保存. 每条豁免写明对象、理由和影响, 使用精确匹配; 前缀匹配必须显式声明. 访问限制或范围排除仍属于未覆盖资源, 不应伪装为已获得.

#### 2.1.1 共享约定与共同盲区

路径映射、编码、实例身份和采样单位等公共约定适合共享无副作用模块, 避免两侧解释不一致. 核对实际调用点使用了该模块. 共享实现可能让采集器和检查器共同漏检, 应用独立样本验证关键边界, 而不是把"共享"本身当作正确性证明.

### 2.1.2 检查不得重建被检查产物

避免导入有构建副作用的入口. 配置和纯函数可以共享, 验证过程不得先覆盖被检查目录再报告通过. aimservices 的案例中, 导入 `build-site.mjs` 重建了外壳, 使未登记编辑消失.

对存在这一风险的检查, 在临时产物中引入一个未登记差异, 确认检查失败且差异仍保留. 不要求对每个低风险文案变更重复执行该实验. `verify-zerodep.mjs` 仅扫描显式字面量依赖, 不证明所有动态导入或构建副作用都不存在.

#### 2.1.3 参数校验

未知参数应报错, 缺值和无效值由调用方校验. `--settle` 与 `--wait` 属于不同脚本的接口, 不可互换. hubtown 曾因参数被静默忽略而实际只观察默认 6 秒, 见案例 §2.1.3.

### 2.2 就绪条件与超时

用可观察状态决定何时采样, 超时只是等待上限. 布局、字体和媒体状态连续稳定可以构成局部就绪判据, 但不保证未来再无变化. 连续次数、间隔和最短时长依据具体风险设定, 不强制套用某个项目的 250 ms/12 次.

无法达到就绪条件时报告前置条件失败. 两侧状态不可比时先解决驱动或环境问题, 不将差异归为产品回归. 重试必须有次数上限且能够改变已识别的失败条件.

### 2.3 执行成本

浏览器启动、页面加载、截图编码和 GPU 负载都可能成为瓶颈. 多路由检查优先复用浏览器并隔离用例状态. 增加并发前测量收益, 负载导致采样漂移时减少并发. macOS 签名检查等平台成本属于特定环境观察, 不作为所有机器的性能模型.

## 3. 结构与运行覆盖

根据可能整体遗漏的单位核对源码: 模块、顶层声明、effect/lifecycle hook、数据行或行为挂载点. 源文件存在不代表功能已执行, 字节相同也不证明驱动达到了对应状态.

大范围排除规则可能同时隐藏应用代码, 应说明分类依据. 代码覆盖、行为状态和输出通道各自报告, 不用一个指标代替其他维度. 构建或部署环境改变时针对受影响路径补测, 无需为了验证而公开部署.

### 3.1 脚本选择

| 对象 | 脚本 | 覆盖边界 |
|---|---|---|
| 镜像与清单 | `verify-mirror`, `verify-refs-served` | 已发现资源与实际响应 |
| HTML 与路由 | `verify-shell`, `verify-ssr`, `verify-routes` | 配置的外壳、提取器和路由 |
| 序列化载荷 | `verify-payload`, `verify-nextdata`, `verify-lenprefix`, `verify-flight` | 支持的格式及规范化规则 |
| 页面加载 | `probe`, `sweep-routes`, `verify-offline` | 已执行状态及静态扫描范围 |
| 数值与视觉 | `verify-tween`, `verify-crossside`, `verify-harvest`, `pixelcompare`, `pixel-walk` | 配置输入与采样状态 |
| 模块与来源 | `cold-audit-modules`, `cold-audit-decls`, `verify-symbols`, `verify-module-map` | 对应产物结构, 不可互换 |
| 构建与独立运行 | `verify-fresh`, `verify-standalone`, `verify-reassembly` | 构建参数、复制范围与产物 |
| 脚本依赖 | `verify-zerodep` | 显式字面量依赖扫描 |

参数见 `scripts/README.md` 与各脚本 `--help`. `--allow-absent` 是布尔选项, 不是豁免文件; 不同 `--allow*` 选项的匹配语义以对应脚本为准.

## 4. 常见问题

注意 CDP 事件覆盖、SRI 拦截、WebGL 读回错误、超时、错误实例连接和未完成就绪. 非空截图、零控制台错误或单次 meanAbsDiff 为零均不是完整页面行为的证明. 环境诊断见 `environment-traps.md`, 具体故障见 `gate-failure-modes.md`.

## 5. 验证产物

保存复现命令、必要输入、环境与状态、结果及尚未覆盖的部分. 大型截图或受许可限制的数据按项目要求存放, 需要可追溯时保留位置与摘要. 是否纳入 Git 遵守已有约定, 不自动提交或分发原始资产.

诊断原始值可以保留在独立日志中. 比较记录明确区分稳定状态与运行时刻, 不删除有助于解释失败的证据. 差异归因与通过判据分别报告, 避免把"已登记差异"写成"无差异".
